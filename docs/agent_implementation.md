## 各 Agent 技术实现建议

### 3.1 DP 动态规划调度 Agent

**技术选型**

- 开发框架：Spring Boot 3.x + Spring AI
- 流程编排：Spring Statemachine（状态流转与链路管控）
- 状态存储：Redis 7.x（会话上下文、全局执行状态缓存）
- 容错组件：Resilience4j（熔断、降级、超时重试）
- 链路追踪：MDC + 全局 TraceId

**核心实现逻辑**

1. **会话上下文管理**：为每轮对话生成全局唯一`conversation_id`，将用户信息、历史消息、标签数据、执行状态聚合为会话上下文，存储于 Redis 并设置 24 小时过期；每次请求通过`conversation_id`还原上下文，实现多轮对话记忆继承。
2. **动态路由编排**：基于语言分析 Agent 输出的意图标签，匹配预设执行链路规则，支持三种执行模式：
    - 串行模式：日常对话 → 分析→对话→合规→输出
    - 并行模式：多维度数据查询同时触发，结果聚合后返回
    - 分支模式：根据意图标签路由到任务 / 检索 / 对话不同分支
3. **结果聚合与转发**：接收各 Agent 执行结果，按链路顺序聚合后写入会话上下文；执行到末端节点时，封装为统一响应格式返回前端。
4. **异常容错处理**：将所有 Agent 调用封装为可重试单元，配置重试次数与超时阈值；调用失败时按业务等级降级，如检索失败返回兜底话术，报告生成失败提示用户稍后重试。

**关键技术要点**

- 采用门面模式封装所有 Agent 调用，对外提供统一调度入口
- 会话上下文支持快照机制，异常时回滚到上一稳定状态
- 链路规则可配置化，存储于数据库支持热更新，无需重启服务

### 3.2 语言分析 Agent

**技术选型**

- 模型层：Spring AI 接入通义千问 / DeepSeek 大模型（深度分析） + 轻量文本分类模型（前置粗筛）
- 输出管控：JSON Schema 强制结构化输出
- 提示工程：Few-Shot 示例 + 角色指令 + 标签体系约束

**核心实现逻辑**

1. **三级标签体系固化**：预先定义标准化标签字典，作为模型输出的强制约束：
    - 一级大类：情绪类、意图类、心理特征类、任务类
    - 二级细分：情绪（愉悦 / 平静 / 焦虑 / 低落 / 愤怒 / 疲惫等）、意图（闲聊 / 咨询 / 查询 / 任务指令）
    - 三级具象：心理特质（内归因 / 外归因、完美主义、低自尊等）、任务类型（日报 / 周报 / 自定义报告 / 数据统计）
2. **结构化解析流程**：构建专用分析 Prompt，传入「用户输入 + 上下文 + 标签体系」，通过 JSON Schema 强制输出包含「标签列表、置信度、语义核心摘要」的结构化结果；输出后自动做格式校验，不合格则自动重试 1-2 次。
3. **性能分层优化**：短文本先通过轻量分类模型做粗分类，识别为简单闲聊时跳过深度心理分析，仅做基础情绪打标，降低调用成本与响应延迟。

**关键技术要点**

- 维护标签示例库，通过 Few-Shot 提示提升标签准确率
- 置信度低于 0.7 的标签标记为「待确认」，不写入正式画像库
- 支持批量异步打标，用于历史对话数据的回溯处理

### 3.3 用户对话 Agent

**技术选型**

- 模型层：Spring AI 接入共情能力强的对话大模型
- 模板管理：字符串模板引擎（Prompt 场景化模板）
- 输出方式：支持 SSE 流式输出

**核心实现逻辑**

1. **多场景 Prompt 模板**：按场景拆分 4 类基础模板，模板中预留「用户输入、情绪标签、上下文、检索结果」占位符：
    - 日常闲聊模板：轻松自然，保持对话连贯性
    - 情绪安抚模板：共情优先，先承接情绪再展开对话
    - 任务通知模板：清晰明确，同步进度与结果
    - 结果告知模板：结构化呈现，重点突出
2. **情绪适配生成**：根据语言分析 Agent 输出的情绪标签，动态调整回复语气与策略；如用户焦虑时自动注入共情话术，用户低落时增加正向引导。
3. **上下文长度控制**：从会话上下文中截取最近 8 轮对话作为历史上下文，超长时对更早消息做摘要压缩，控制 Token 消耗。

**关键技术要点**

- 人设指令固化在 System Prompt 中，保证回复风格一致性
- 生成结果先返回调度 Agent，经合规校验后再输出给用户
- 支持流式输出，逐字返回提升对话体验

### 3.4 检索 Agent

**技术选型**

- 向量数据库：Milvus 2.x（对话向量、知识库向量存储）
- 关系数据库：MySQL（对话原文、标签元数据存储）
- 向量嵌入：Spring AI Embedding + 通用文本嵌入模型
- 检索策略：混合检索（向量语义检索 + BM25 关键词检索）

**核心实现逻辑**

1. **双数据源检索能力**
    - 历史对话检索：支持时间范围、情绪标签、关键词多维度过滤；先通过向量召回 TopK 语义相关记录，再通过关键词重排序返回最终结果。
    - RAG 知识库检索：将心理科普、情绪调节方法等文档分块向量化存入 Milvus；咨询场景下，通过用户问题向量召回最相关知识片段，作为建议生成的依据。
2. **数据写入同步**：对话消息归档时，异步调用嵌入模型生成向量，写入 Milvus 并关联消息 ID；知识库新增 / 更新时，自动触发分块与向量化。
3. **统一结果封装**：所有检索结果统一返回「内容、相关性得分、元数据（时间 / 标签 / 来源）」格式，便于上层 Agent 处理。

**关键技术要点**

- 对话按单条消息向量化，知识库按 200-500token 分块向量化
- 混合检索权重可配置，平衡语义匹配与关键词匹配精度
- 检索强制带`user_id`过滤条件，严格实现用户数据隔离

### 3.5 任务执行 Agent

**技术选型**

- 任务调度：Quartz（单机部署） / XXL-JOB（分布式部署）
- 状态管控：轻量状态机（任务状态流转校验）
- 持久层：MyBatis-Plus + MySQL

**核心实现逻辑**

1. **全生命周期管理**：定义任务状态枚举：待执行、执行中、已完成、已失败、已取消；通过状态机控制流转，禁止非法状态跳转。
2. **任务拆解执行**：接收任务指令后，按任务类型匹配拆解规则，将复杂任务拆分为有依赖关系的子任务；例如「生成周报告」拆解为：拉取历史数据→指标统计→报告生成→合规校验四个步骤。
3. **定时周期任务**：日报、周报、月度画像更新等周期任务，通过调度框架创建定时触发器，到期自动触发；支持任务暂停、恢复、取消操作。
4. **进度同步机制**：子任务执行完成后更新任务进度，通过调度 Agent 触发对话 Agent 向用户同步进度。

**关键技术要点**

- 任务执行幂等性：通过任务 ID + 执行批次号保证重复执行不重复生成结果
- 失败自动重试：子任务失败默认重试 2 次，超过次数标记任务失败
- 所有任务与用户绑定，支持按用户查询任务列表与历史记录

### 3.6 合规检查 Agent

**技术选型**

- 前置过滤：AHKFilter 敏感词过滤器（本地词库）
- 深度校验：大模型语义合规校验
- 风险规则：自定义规则引擎（高危场景判定）

**核心实现逻辑**

1. **两级校验机制**
    - 一级校验：本地敏感词匹配，毫秒级快速过滤常见违规内容；命中后直接拦截或替换。
    - 二级校验：大模型语义校验，针对心理场景专项检查：禁止精神疾病诊断、禁止医疗建议、禁止负面引导、识别自伤 / 伤人倾向。
2. **分级处理策略**
    - 轻度违规：返回修改意见，触发对应 Agent 重生成
    - 中度违规：拦截输出，返回标准化兜底回复
    - 重度违规（自伤 / 伤人风险）：立即拦截，输出正向干预话术，并记录风险日志
3. **动态规则更新**：敏感词库、风险规则支持热更新，无需重启服务。

**关键技术要点**

- 输入输出双校验：用户输入先校验，Agent 输出再校验，全链路覆盖
- 心理场景专项规则：所有建议必须标注「仅供参考，不构成医疗诊断或建议」
- 所有拦截操作留痕，违规日志持久化存储

### 3.7 用户画像与报告 Agent

**技术选型**

- 统计层：MySQL 聚合查询 + 自定义统计服务
- 生成层：Spring AI + 大模型报告生成
- 输出格式：Markdown 文本 + JSON 结构化指标
- 可视化支持：输出标准化统计指标供前端 ECharts 渲染

**核心实现逻辑**

1. **用户画像构建**
    - 定时聚合：每日凌晨聚合当日所有对话标签，统计各维度标签频次、占比、变化趋势
    - 画像维度：情绪特质（主导情绪、情绪波动指数）、心理特征（归因风格、自尊水平、应对方式）、行为模式（活跃时段、高频话题）
    - 版本管理：每次更新生成新版画像，支持不同版本纵向对比
2. **分析报告生成**
    - 数据准备：接收任务参数，拉取对应时间范围的对话数据、标签统计与画像数据
    - 内容生成：将统计指标 + 典型对话片段输入大模型，按预设结构生成报告，包含情绪走势、心理特征总结、变化原因分析、优化建议
    - 多格式输出：同时返回 Markdown 全文与 JSON 格式统计指标，分别用于阅读与图表渲染

**关键技术要点**

- 画像仅基于对话数据生成，不做过度推断
- 报告模板可配置，支持日报、周报、月报、自定义周期等多种模板
- 样本量不足时明确标注「数据有限，结论仅供参考」
